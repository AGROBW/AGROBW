# Seller Store Insights - Metric Contract

## Access

Seller Store Insights is exclusive to an authenticated store owner with an active
subscription whose plan has `has_seller_store = true`. The database is the source
of truth for entitlement checks. Client-side visibility is not authorization.

Historical insights are unavailable while the entitlement is paused or expired.
Raw analytics rows are never readable by browser roles.

## Metrics

| Metric | Definition |
| --- | --- |
| Store visits | Distinct `site_page_views.session_id` values for the store slug and period. |
| Product opens | Distinct sessions with an `announcement_open` event attributed to the store. |
| Contact actions | Distinct sessions with `contact_whatsapp` or `contact_platform`. |
| Conversion rate | Distinct sessions with a contact action divided by distinct store visitors. |
| Website clicks | Accepted `website_click` events. |
| Store shares | Accepted `store_share` events. Sharing is not a contact action. |
| Catalogs generated | Accepted service-side `catalog_generated` events. |
| Catalog downloads | Accepted service-side `catalog_download` events. |
| Catalog QR opens | Accepted `catalog_qr_open` events tied to a catalog and announcement. |

Periods supported by the product are 7, 30 and 90 civil days in
`America/Sao_Paulo`. Comparisons use the immediately preceding period with the
same number of days.

## Source channels

The normalized channels are `direct`, `internal`, `google`, `whatsapp`, `social`,
`catalog_pdf` and `other`. Query strings and raw referrers must not be persisted in
the Seller Store Insights event table.

## Event contract

Browser events:

- `store_visit_attribution` (source breakdown only; it does not replace the visit metric)
- `announcement_open`
- `contact_whatsapp`
- `contact_platform`
- `website_click`
- `store_share`
- `catalog_qr_open`

Service-only events:

- `catalog_generated`
- `catalog_download`

An announcement referenced by an event must belong to the store owner and remain
active. A QR event must reference a catalog generated by the same store and an
announcement included in that catalog.

## Privacy and integrity

- Raw session identifiers are transformed into a store-scoped hash before storage.
- The table stores no visitor user ID, IP address, user agent, raw referrer, contact data or free-form metadata.
- Events produced by the authenticated store owner are ignored.
- Browser retries use `event_key` idempotency.
- Equivalent events are deduplicated in five-minute buckets.
- Each session is limited to 30 accepted attempts per minute.
- Raw events have a 180-day retention contract.
- Raw events tied to a deleted store, announcement or catalog follow that entity's deletion lifecycle.
- `anon` and `authenticated` cannot read or mutate the raw table directly.

## Delivery phases

Stage 1 establishes this contract, storage and authorization.

Stage 2 instruments browser actions from the public storefront. It reuses the
existing site analytics session, normalizes traffic sources before transmission,
propagates only the store slug and source channel to announcement pages, and
records platform contact only after a message is successfully sent. Analytics
failures never block navigation or contact flows.

Dashboard UI, catalog attribution and production rollout remain separate stages
and must preserve these definitions.

Stage 3 provides owner-only aggregation for 7, 30 and 90 civil-day periods in
`America/Sao_Paulo`, including previous-period comparisons, daily series,
normalized visit sources and top announcements. Store visits still come from
`site_page_views`; `store_visit_attribution` is used only for their source
breakdown. Raw rows and session identifiers remain unavailable to the browser.

Stage 4 adds the on-demand `Desempenho` workspace to `Minha Loja`. The UI is
exclusive to an active Seller Store entitlement, consumes only the aggregate
RPC, and includes period comparisons, daily trends, normalized sources, top
announcements, commercial actions and privacy-aware loading, empty and error
states.
